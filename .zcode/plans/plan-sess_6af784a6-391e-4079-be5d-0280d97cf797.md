# Feature : KPI personnalisables (drag & drop, choix, numérotation impression, redimensionnement)

## Décisions prises
- **Persistance** : colonne `dashboard_layout` (JSON en TEXT) sur la table `users` — suit le précédent `lastEnv` (préférence 1:1, pas de JOIN, pas de modèle supplémentaire).
- **Redimensionnement** : largeurs discrètes sur la grille 3-colonnes existante (`1` = 1/3, `2` = 2/3, `3` = plein).
- **Ordre d'impression** : **indépendant** de l'ordre écran — un tableau `printOrder: KpiId[]` dédié.
- **DnD** : natif HTML5 (déjà le pattern du codebase dans `board-grid.tsx`) — **aucune dépendance** ajoutée.

## Modèle de données
```ts
type KpiId = 'charge' | 'otd' | 'stock' | 'lignes' | 'stockTable'
type KpiWidth = 1 | 2 | 3
interface KpiLayoutItem { id: KpiId; visible: boolean; width: KpiWidth }
interface DashboardLayout { items: KpiLayoutItem[]; printOrder: KpiId[] }
```
Layout par défaut (reflète la disposition actuelle) :
```ts
{ items: [
    { id: 'charge',    visible: true, width: 1 },
    { id: 'otd',       visible: true, width: 1 },
    { id: 'stock',     visible: true, width: 1 },
    { id: 'lignes',    visible: true, width: 2 },
    { id: 'stockTable',visible: true, width: 2 },
  ],
  printOrder: ['charge','otd','stock','lignes','stockTable'] }
```

## Phase 3 — Frontend : mode édition (drag, resize, numérotation)

### 3.1 État local
- `layout` signal initialisé depuis `props.layout` (prop Inertia).
- `editMode()` signal (toggle bouton "Personnaliser").
- `printing()` signal piloté par `beforeprint`/`afterprint` (pour l'ordre d'impression).

### 3.2 Sauvegarde auto (debounce 600 ms)
- `saveLayout(layout)` → `PATCH /api/v1/user/dashboard-layout`.
- Déclenchée à chaque mutation (reorder/resize/visibility/printOrder).
- Toast `solid-sonner` de confirmation léger.

### 3.3 Drag & drop pour réordonner (HTML5 natif)
- En mode édition : chaque carte a une poignée (☰ `drag_indicator`).
- `onDragStart` → `setDraggedId(id)` ; `onDragOver` → `preventDefault` + marquage cible ; `onDrop` → réordonne `layout.items`.
- Placeholder visuel (bordure pointillée) à la position cible.
- Suit exactement le pattern de `board-grid.tsx:515-529` (`dataTransfer`, `effectAllowed: 'move'`).

### 3.4 Redimensionnement
- En mode édition : mini segmenté `[⅓ | ⅔ | plein]` dans l'en-tête de chaque carte.
- Met à jour `item.width` → `WIDTH_CLASS` → sauvegarde.

### 3.5 Numérotation d'impression (indépendante)
- Badge numéro toujours visible sur chaque carte (= position dans `printOrder`), style discret.
- En mode édition : fléches ▲▼ pour déplacer le KPI dans `printOrder`.
- Ordre écran ≠ ordre impression : deux tableaux distincts.

### 3.6 Plateau "KPI masqués"
- KPI avec `visible: false` → affichés dans une barre en bas (mode édition) avec bouton "Afficher".
- Réutilise le style `HiddenCard` existant (lignes 169-189).

### 3.7 Boutons mode édition
- Dans les `actions` du `Masthead` ou en haut de grille : "Personnaliser" / "Terminé" / "Réinitialiser" (reset → `DEFAULT_DASHBOARD_LAYOUT`).

## Phase 4 — Impression respectant `printOrder`

### 4.1 Ordre d'impression via CSS `order`
- Sur chaque carte : `style={{ order: printing() ? printOrder().indexOf(id) : indexÉcran }}`.
- Signal `printing()` basculé par listeners `beforeprint`/`afterprint` (posés à côté de `usePrintFitPage`).
- En impression, `grid-auto-flow:dense` + `order` reflow les cartes dans l'ordre de `printOrder`.

### 4.2 Ajustements CSS `resources/css/app.css` (`@media print`)
- Masquer les contrôles d'édition (poignées, segmentés resize, fléches) via `print:hidden` (déjà sur les contrôles).
- Le badge de numérotation reste visible à l'impression.
